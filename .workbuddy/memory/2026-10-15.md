## 修复：模型设置「保存无反应」—— CSRF 会话错位（多页面实例互踢）

- 症状：控制台输入 API Key 后点「保存模型设置」无反应、Key 未保存；api.log 中大量
  `PUT /api/settings/models 403 Forbidden`（≥25 次）。
- 根因：`POST /api/session` 每次调用都签发新会话并覆盖浏览器共享 Cookie，而每个控制台
  页面把 csrf_token 存在自己内存（ApiClient.csrf）。服务重启/多标签页导致多个页面实例
  各自 signIn，除最后一个之外所有页面的令牌立即失效 → 所有写请求 403；GET 不校验
  CSRF，所以页面看起来正常、只有保存失败。
- 修复：
  - `api/routes.py::create_local_session` **幂等化**：`auth.verify_cookie` 有效即复用
    （返回现存 csrf_token + `reused` 字段），不再签发覆盖 Cookie。安全语义不变
    （csrf 本就只发给持 cookie 的页面；错位令牌仍 403）。
  - `web/src/api/client.ts`：新增 `withSessionRetry`，写请求（write/deleteSession/
    saveModelSettings）遇 401/403 自动 signIn 并重试一次；csrf 为空先 signIn。
  - 新增 3 个回归测试（tests/integration/test_web_model_settings.py）：复用令牌可用、
    无 Cookie 才新签发、错位令牌仍被拒。
- 验证：ruff / pyright / check_encoding 全过；`pytest tests/unit tests/integration`
  503 passed + 2 skipped；`pnpm build` 重建 web/dist（新资产 index-DnBMOHUp.js）。
- 待办（用户执行）：重启 start-workbench.cmd 使后端新代码生效，刷新页面后重新配置 Key。

## 诊断：数据库容器打不开 —— Windows 端口保留吞掉 55432

- 症状：`workbench-postgres` 停止；`docker compose up` 报
  `ports are not available ... 127.0.0.1:55432 ... access permissions`。
- 时间线：17:00 正常关机（容器被干净停止，exit 0，数据卷完好）→ 18:28 开机 →
  18:33 Docker Desktop 启动，容器未被自动恢复（关机停止算"显式停止"，unless-stopped
  不恢复）。**关键**：本次开机 Windows 动态保留段把 `55338-55437` 划走（排除表里共
  54638-55792 多段），55432 落在其中 —— 无进程监听但任何 bind 都 WinError 10013
  （EACCES）。非管理员 shell 直接 bind 55432 已复现。
- 结论：非 Docker/数据问题，是 Windows(Hyper-V/WinNAT) 每次开机随机"抽签"抽中项目端口。
- 修复（需管理员，已交用户执行）：`net stop winnat` → `netsh int ipv4 add
  excludedportrange protocol=tcp startport=55432 numberofports=1 store=persistent`
  → `net start winnat`；无效则试 `net stop/start hns` 或换端口。
- 待验证：用户执行后由控制端 `docker compose up -d --wait postgres` 拉起并 pg_isready。

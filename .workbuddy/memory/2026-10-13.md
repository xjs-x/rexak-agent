# 2026-10-13 · 第二版（v2）落地实施

依据 `docs/implementation-v2-plan.md` 落地六个批次，控制端 + 执行端一次性提交。

## 交付的能力变化（能力视角）

1. **不完整响应不再静默进入等待。** 新增 `models/response_quality.py`（纯分类器）与
   `agent/middleware/response_recovery.py`（官方 `awrap_model_call` 接缝）。
   截断/空/破损工具/拒绝 → 有明确分类、有限恢复（默认初次 + 最多两次）、
   恢复耗尽抛 `ModelResponseUnavailable` 由 Runner 落 `failed`。
   `logical_call_id` 走 ContextVar 贯穿恢复周期，重启后从 model_calls 读已用额度。
2. **并行登记同一入口不再唯一键冲突。** `domain/assets.py` 改为
   `INSERT ... ON CONFLICT (uq_assets_endpoint_identity) DO UPDATE`，不再 rollback 外层事务；
   只更新 `last_seen_at` 与缺失的 `source_artifact_id`。
3. **焦点自动承接。** 新增 `agent/focus.py::resolve_focus`（纯函数），
   `update_plan` 与 WorkingContext 共用；`current_focus.source = explicit | plan_inferred`。
   `update_plan` 扩展 `assessment_json`（轻量判断，`work_assessment`）与
   `steps_json=None`（保留计划）。
4. **结构化请求构造。** `contracts/http.py` 为协议真源，执行端同步副本
   `workbench_executor/http_encoding.py`；form/multipart 由执行端编码
   （CRLF、boundary、Content-Disposition），手工 multipart 头被拒；
   Executor capabilities 增加 `body_modes`，控制端调用前检查。
5. **进展与相似结果分离。** `progress.py` 的知识签名不再包含 `request_digest`；
   新增 `activity_signature`、`similar_result_signature`（保守、标 low 置信）。
6. **报告与压缩解耦。** 阶段签名含领域有效版本 + 完成步骤 + 判断修订；
   首次看到实质内容即生成快照（不再一律设基线跳过）；区分生成时间与覆盖位置。

## 关键实现坑（值得记）

- **结论**：`AIMessage` 的 pydantic 校验拒绝非 dict 的 `tool_calls[].args`；
  测试"分片未拼完的参数"必须用 `AIMessage.model_construct(...)` 绕过校验。
- pyright 对 `TypedDict` 的 `NotRequired` 键禁止直接下标访问 → 用 `.get()`。
- `state` 参数在 middleware 基类里是 `AgentState`，`dict(state)` 会得到
  `dict[str, object]`；需要 `cast("dict[str, Any]", dict(state or {}))`。
- `pg_insert(AssetRow.__table__)` 需要 `cast(Any, ...)` 才能过 pyright。
- 本机 pytest 在结束时清理 tmp 目录会触发环境的 safe-delete 守卫
  （>50 文件批量删除被拦），导致**进程被杀、summary 丢失**。
  规避：`-v` 逐条输出（失败行随行打印），或用 `--junitxml`；
  退出码非 0 不代表用例失败，要看 `FAILED` 计数。

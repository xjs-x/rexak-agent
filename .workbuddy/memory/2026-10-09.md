## 追加：独立复核指出的三处问题（已全部修复，commit `785907e`）

复核结论是"最小纵向链路成立，但暂不能签收 P2"，指出三处必须修的问题。

### 1. 方向变更不能可靠拦截旧模型响应

**根因**：`ToolDispatchMiddleware` 在参数里没有版本信息时退化成
`int(args.get("__control_version__", run.control_version))` —— 拿数据库当前值和
当前值比，恒等。`_assert_dispatch_allowed` 也只查所有权与暂停/取消。

**修复**：`CommandGuardMiddleware` 在**模型请求前**固定 `control_version`
（写入图状态 `dispatch_control_version` + `Toolbox.control_version`）；
派发时用固定值与当前值比较；不一致不执行并写 `stale_response_blocked` 事件；
固定值缺失时 **fail-closed**。`assert_control_current` /
`_assert_dispatch_allowed` 改为接收固定版本（不再自读自比），新增
`StaleResponseError`。

**测试**：`tests/integration/test_control_version.py` —— 用会在 `_generate()`
期间**真的改库**的脚本模型制造真实并发时序，不是手动 raise。

### 2. 重启恢复顺序与设计承诺相反

**根因**：`run_startup_recovery` 先把 `recovering` 改 `queued`，再核对远端 job。

**修复**：新顺序 = 标记 recovering → **核对远端** → 按结果决定归宿。
`unknown` / `sync_status=uncertain` / 执行岛不可达一律保持 `recovering`，
写原因 + `input.required` 事件。`resume` 对 `recovering` 强制要求
`acknowledge_unknown_operations=true`。

**演练额外暴露并修掉的 4 个缺陷**：
1. 执行岛返回 **404 导致整个核对崩溃**（`ExecutorRejected` 没被捕获）→ Runner 退出码 1；
2. 单个 job 异常中断整次核对；
3. 核对**串行**走 SSH，上百条 job 时把恢复拖到几分钟，Runner 进不了正常调度
   → 改为有界并发 `JOB_RECONCILE_CONCURRENCY=8`；
4. `recover_stale_runs` 用 `now - lease_seconds` 当截止，等价于"过期后再过一整个
   lease 周期才算 stale"，与文档承诺不符 → 改为 `lease_until < now`。

**新增 CLI**：`workbench runner --only-run-id <id> --no-recover`（定向驱动/跳过恢复）。

**进程级演练**：`scripts/restart_drill.py`（**已通过**）—— 独立进程启动真实 Runner、
派发 `/slow?delay=8&chunks=4`、任务在途时 `kill()`、等 lease 过期、跑真实恢复、
重启 Runner，最后用**目标端服务端计数器**证明 `/slow` 只执行 1 次。

### 3. 标准验收命令不能原样复现

- `uv run pytest` 报 `No module named 'tests'`：console script 不把 CWD 放进
  `sys.path`（`python -m pytest` 才会）。修：`pythonpath=["."]` + `tests` 显式建包。
- `workbench doctor` 在 cp936 下崩：子进程按 locale 写 GBK，父进程按 UTF-8 解码，
  异常在读线程里被 `subprocess` 吞掉 → `proc.stdout` 变 `None` →
  `AttributeError`。修：`child_process_env()` 给所有子进程注入
  `PYTHONUTF8/PYTHONIOENCODING`；`configure_stdio_utf8()` 把入口自身输出切 UTF-8。

### waiting_tool 事件唤醒（`bc00268`）

- 片段结束时若有非终态后台任务，run 进 `waiting_tool` 并返回（**不阻塞、不空转**）；
- Runner 常驻循环里做唤醒巡检（无等待中的 run 时只是廉价查询，不碰执行岛）；
- 唤醒通知作为 MESSAGE 指令入队，由 `CommandGuardMiddleware` 在一致边界注入，
  **不伪造**对应原 tool_call 的 tool 消息（§8.3）；
- **`unknown` 不是确定结论**：只认 succeeded/failed/cancelled。unknown 表示
  "既不能证明完成、也不能证明没发生"，据它唤醒等于在未知副作用上继续推进。
  投影照实同步，但唤醒判定另算。
- 顺带修：状态机补 `waiting_tool -> queued`；`_candidate_runs` 去重
  （queued 与 resumable 两分支会命中同一 run，不去重会连续驱动同一个 run 两次）。

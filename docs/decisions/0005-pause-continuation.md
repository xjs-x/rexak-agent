# 0005 · 暂停当前回复，保留对话并接受新指令

- 日期：2026-10-11
- 决策：暂停停止当前 Agent 等待与推进，不关闭聊天；发送新消息隐式继续，也可以新建独立聊天。

## 用户行为

排队、运行、等待工具或等待用户的任务都可以暂停。受理后先显示“正在暂停”，Runner 结束当前等待并落库后显示“已暂停”。暂停后的输入框继续可用，发送新指令会让同一任务重新排队；新聊天不依赖旧聊天恢复。历史回复和操作记录保留。

普通用户指令里的 URL 自动应用到按指令运行的目标规则，不需要包含“加入范围”。兼容旧网页发送的 `scope: {}`，以及旧网页意外创建的空严格范围任务。显式选择严格模式、已有严格规则或显式范围变更的任务保留其设置。

## 实现

- 暂停指令先提交消费状态，再在事务外打断图，避免异常回滚后重复消费暂停。
- API 暂停递增控制版本并进入 `pausing`；调度器取消当前会话的等待任务，Runner 使用合法状态迁移落到 `paused`。其他会话继续调度。
- 新输入记录一次续聊标记。首次进入片段时，使用官方图的 `aupdate_state(config, None, as_node=END)` 收束旧的待执行节点，再用增量输入进入模型。框架源码确认这个入口保留已完成的 pending writes；真实 PostgreSQL checkpoint 测试验证行为。
- 对尚无结果的旧 tool call 补充明确的中断协议消息，避免模型消息结构不完整；该消息不代表工具成功、远端取消成功或测试结论。旧工具不会因新输入自动重放。
- 用户新消息仍由 CommandGuard 从指令表消费一次；历史仍使用官方 checkpointer，没有新增会话历史真源或第二套 Agent 循环。
- Session 与 Run 的共同修改遵守 Session → Run 的锁顺序；刷新数据库行之前先 flush 本事务修改，避免续聊标记被旧值覆盖。
- 流式回复按响应 ID 分组，避免同一任务之前的已归档回复遮住后续回复；暂停时保留已经显示的部分文本。

暂停停止 Agent 对当前工作的推进。已提交到执行端的后台任务保留真实台账，不虚报已终止；需要取消远端工作时使用现有取消流程。常规进程恢复仍走原有核对与幂等路径，没有新用户输入时不会主动丢弃待执行节点。

见 [暂停与续聊验收](../acceptance-results/2026-10-11/pause-continuation.md)。测试包含同一任务续聊、失败阶段后新任务、模型等待时暂停、旧客户端范围兼容，以及实际浏览器的新聊天、发送和删除操作。

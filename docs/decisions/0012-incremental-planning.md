# 0012：现有单 Agent 中的证据驱动增量规划

2026-10-21，用户确认第一轮实现基线。本决定允许增量扩展 PlanStep 的完成语义；不恢复已撤销的责任树、TaskContract、多 Agent 或第二套规划循环。0011 的外部 Skill 边界继续有效。

## 职责与目标

官方 `create_agent` 是唯一模型—工具循环。模型选择继续、修复条件、展开任务或切换路线；程序检查来源、版本、状态与执行约束，不规定下一工具。Runner 继续负责调度与执行控制，Executor 和业务表的权威归属不变，不新增任务数据库。

第一轮验收必须包含两条实际执行链：前提失效后的修复，以及成功结果后的局部展开。只新增计划记录、只通过脚本模型状态检查，均不证明真实模型的自主规划能力。

## 旧快照判断与下一焦点

`update_plan` 使用 `expected_plan_revision`。`work_assessment.evaluated_step_ids/evaluated_plan_revision` 指向更新前的计划；`current_focus` 指向下一工作。判断保存提交时的下一焦点快照与结果计划版本，仅用于判断其中的下一步是否仍适用，不构成另一份焦点权威。

`basis_refs` 为带类型的真实来源，旧 `evidence_refs` 仍仅表示工件。程序检查归属、可读性、哈希及真实操作；直接结果不能伪装成其他任务的执行。需要复用其他任务结果时显式使用 `relation=supporting`，原操作归属保持不变。合法来源不证明模型解释正确。

同批多个 `update_plan` 在派发前全部拒绝。新计划与依赖新焦点的外部执行分批进行，同批独立执行继续关联原快照。更新前后复核既有控制边界；生产 Runner 还核对已提交规划头，并使用官方同步 checkpoint durability，不增加自定义 Graph。

## 分型完成与复查

`completion_spec` 明确 `mode=investigate|achieve`、`done_when`、`check_type=model|predicate|verification`。调查取得明确阴性结果可以结束工作；达成任务必须预期条件成立。不确定结果和执行失败保留为未决工作，不能冒充调查阴性。

模型提交 `completion.outcome/summary/source_refs`；`completion.check` 仅由程序生成：

- `model` 只检查来源与一致性，语义结论仍属于模型判断。
- `predicate` 只检查持久化操作回执的指定标量与预期值，不执行任意表达式，也不证明任意自然语言条件。
- `verification` 引用当前程序验证记录，保留其方法和范围，不传播组合结论。

新完成步骤在结束复查中不再直接跳过。条件、来源、相关弱点版本、当前阶段、身份、范围或控制指令变化时需要复查。完成检查不写 Finding.confirmed，不自动重放工具。

未完成步骤不能直接从列表删除；先标为 dropped 并说明处置理由。归档 done 步骤前也检查完成依据。放弃计划不删除领域未决项、不取消远端资源。修改完成条件后旧检查不能自动沿用。自然语言目标的最终语义仍由模型判断，FinishGate 是一致性门禁。

## 修订、持久化与恢复

计划、焦点、判断和最近修订来源仍归 checkpoint。完整新旧差异与理由落不可变工件链，图状态仅保存有界元数据和引用。稳定更新标识由会话、Run、tool_call_id 派生；同调用不同参数拒绝，同一已提交调用重放不增加修订；纯无变化更新不增加 plan_revision。

工件可先于 checkpoint 存在，存在工件不等于提交成功。Runner 不再把流式 `updates` 当作计划提交回执；从 Saver 的已提交 `channel_values` 生成带 checkpoint 来源的幂等事件。事件事务失败后，由下一次续跑或计划 API 读取补投影。事件、工件或投影失败不触发外部操作重放。

状态 schema 升级为 6。1–5 顺序迁移，保留消息、操作身份与待执行节点；旧 done 标记为历史完成待复查，不补造完成模式、依赖或验证。旧判断无法推断其真实评估对象，明确保持未知。未提交并行结果不能安全迁移时拒绝恢复并要求核对，不猜测重放。历史终态 Run 不因升级自动启动。

## 持续推进与边界

WorkingContext 呈现变化、条件缺口、完成条件与判断来源；新结果不强制修改计划。Progress 的事实进展签名不再包含判断措辞或当前焦点，重排与切换不能制造知识进展。重复结果只触发软提醒，不因固定次数结束，不设任务总时长或费用硬上限。

成功结果应使模型判断可用条件与后续工作，使用已有执行模板时固定版本；注册不等于实测可用。第二轮的 PlanStep depends_on、AND/OR DAG、评分器和独立 Planner 不在本次实现范围。

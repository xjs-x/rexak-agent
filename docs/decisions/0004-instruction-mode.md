# 0004 · 默认按用户指令应用目标

- 日期：2026-10-11
- 决策：个人工作台默认使用 `instruction` 模式；`scoped` 为可选严格模式。
- 原因：用户希望直接在聊天里给出测试目标，不再逐次配置 scope。

## 行为

直接聊天和未提供 scope 的会话创建默认按指令运行。用户初始目标、补充消息和恢复指令里的 HTTP/HTTPS URL 或 IPv4 会自动转换成目标规则；URL 中的 IPv6 主机同样可识别。规则允许同一明确主机的协议与端口探索，不自动包含子域或其他主机。示例、否定语句里的地址不作为新增目标，模型回复和工具输出也不作为目标授权来源。

严格模式仍按用户设置的协议、主机、端口匹配，不随聊天自动扩大。没有目标地址时可以聊天，但网络工具会要求用户在聊天里提供目标，无需配置表单。

旧版没有 `mode` 字段的任务，在提交新消息、恢复或 Runner 开始片段时转入按指令运行，并读取此前的用户目标。新版本显式选择的严格模式保持严格模式。

旧网页创建请求没有显式 `mode` 时，即使包含空 `scope` 对象也使用按指令模式。此前由工作台创建、没有显式模式选择记录、规则为空且没有范围变更记录的任务同样兼容；其他严格任务保持原设置。普通“测试这个网址”指令即可触发应用目标。

## 实现归属

仍然只使用 `Session.scope_snapshot` 作为目标规则真源。自动目标变更在事务内更新修订、递增 `Run.control_version` 并写事件；模型前刷新 Toolbox，旧版本响应沿用已有派发拦截。模型上下文及 manifest 记录实际模式与范围修订。

Executor 继续接收既有协议中的具体主机规则，无需更新执行端。没有新增第二套 Agent 循环，也没有增加目标专属提示词。自然语言约束仍作为用户原文交给模型；地址提取器不承担完整的自然语言理解。

## 验证

见 [运行模式与连接验收](../acceptance-results/2026-10-11/instruction-mode.md)。数据库测试覆盖自动追加目标、幂等修订、旧任务恢复、严格模式和运行时刷新；独立浏览器覆盖直接聊天、严格模式选择、断线重连与创建后的读取失败。真实模型渗透效果没有在本次变更中重新评测。

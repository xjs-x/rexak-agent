# 0013：动态规划闭环 P0/P1 修复

日期：2026-10-21。接续 0012；用户将 P2 真实模型回归留作自行执行。

## 边界

保留单 Agent、官方 create_agent、整体计划提交与 Runner/Executor 控制边界。不引入 Planner、额外验证模型、依赖 DAG、Patch 接口或第二份 Plan 权威。原始执行归属不可修改。

## P0：来源与完成

引用工件、操作、观察或验证记录时，程序追溯原始操作，自动将跨步骤来源规范化为 supporting，并记录原步骤和实际操作链。模型不需要自行记忆 relation 参数。

真实性检查包括同会话、真实操作、成功状态及工件可用性/哈希。适用性核对当前授权、执行策略、已有身份认证版本，以及声明的 not_before。not_before 使用操作创建时间作保守下界，没有隐式 TTL。历史认证信息缺失只能作为受限历史观察，不能宣称当前认证能力已被独立证明。

新操作额外采集所依赖的条件快照。增加新条件不撤销原有条件；修改或否定原条件则要求复查。旧操作没有条件内容快照且条件版本发生变化时，调查可记录有明确限制的历史观察，不能据此直接完成达成型任务。

HTTP 的 model 完成记录须声明 http_checks（方法、无凭据/无查询载荷的端点，可指定身份和认证方式）。每项须匹配引用来源中的真实成功操作和 HTTP 状态回执。OPTIONS 不代替 PUT，不同路径、身份和认证方式不互相冒充。

检查分开表达 source_authenticity、source_applicability、sufficiency。HTTP 范围检查只证明声明的请求工作发生过；不核验自然语言范围是否完整、参数是否满足漏洞前提、正文是否证明漏洞。模型判断、指定回执字段与已有独立验证记录各自保留限制，不升级 Finding。

错误返回逐步骤原因、缺失范围、已有回执与修复提示。整批仍原子提交；失败不重放外部工具。未变步骤可仅列 step_id，字段沿用；程序字段只有与 checkpoint 完全一致时才能随读回记录携带，不能伪造。

## P1：使用与观测

初始计划后的增项、主动切换、受阻/放弃和已声明 HTTP 范围改变，需要同次更新携带简短 assessment_json：changed、next_action、decision、basis_refs。旧版本与旧焦点由程序补齐，模型显式提供时仍须校验旧快照；普通请求、单纯完成登记和自然承接不强制填表。

WorkingContext 增加有界的已有结果目录和待收尾工作：操作、工件、原焦点、方法、端点、身份、状态及声明范围匹配入口。它是只读目录，不代表完成验证通过，也不指定下一工具。

修订的 changed_step_ids 只记录内容变化；新增、移除和保留步骤的相对顺序变化分别记录。修订工件链和提交后事件投影继续沿用 0012。

新 Run 在装配前标为 unbound；Runner 装配后记录实际 prompt_version、已加载规划入口/合同/提示指纹及激活历史。该指纹不冒充整个进程的字节码版本；磁盘源码树指纹独立保留。健康检查和 Runner 启动日志提供同范围版本，便于核对已运行进程。

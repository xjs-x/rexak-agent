# 0014：第一阶段最小自主安全测试闭环

日期：2026-10-22。按本轮用户要求取代 0012、0013 中强制规划、Assessment、完成证明和领域结束门禁；历史数据与来源记录保留。

官方 `create_agent` 仍是唯一模型—工具循环。模型通过正常消息分析结果、选择下一动作或结束；程序负责授权、控制版本、租约、幂等、执行状态、工件真实性和 checkpoint。

生产路径停止 Assessment、StageReport、Progress 主动判断、Coverage 维护与结束复查、专用 Verification 工具和 Skills。旧数据库表、历史报告、校验器与读取适配暂留；旧图节点只通过无副作用兼容节点恢复，不运行旧协议。

`update_plan` 使用最多 20 步的局部 upsert，仅修改提交的步骤。`step_id` 稳定，`expected_plan_revision` 必填，计划和焦点共用一个修订号；同批多写者全部拒绝。完成步骤只表示模型的工作记录，不能提升 Finding。焦点是一段可选调查方向，可独立于计划存在。

`propose_completion` 只提交回答、可选限制与工件引用。模型正常无工具最终回复也是结束信号，由同一 FinishGate 检查。结束不要求关闭全部假设或可选步骤；待消费指令、未决/未知执行、明确等待条件及伪造引用仍不能被忽略。结果由 checkpoint 和 Runner 持久化，不建立第二份会话权威。

状态版本升级到 7；兼容字段只供旧 checkpoint/导出读取。迁移保留消息、原操作身份与待执行节点；存在未提交并行结果或无法保持原节点边界时拒绝迁移，不重放不确定副作用。旧工具参数在派发时明确拒绝，作为 ToolMessage 反馈，禁止静默丢弃。

验收使用隔离 PostgreSQL、本地受控工具和脚本模型。真实模型/API Key 与真实靶场由用户另行测试。本阶段不引入信息图、RAG 或新反思系统。

# 执行资源使用与维护

本机仍通过桌面 **Rexak Agent** 打开，执行发生在指定 Kali。控制台“执行资源”页分别展示待完成工作、保留资源、历史结果和值班。

`run_command` / `run_script` 默认独立执行、等待 10 秒；等待到期返回同一个资源 ID。`background=true` 尽快返回。只有显式设置 `execution_timeout_seconds` 才有执行截止。脚本参数经 stdin JSON 传递，argv 按数据传递；同会话各轮共享工作区。任务依赖放工作区 venv，系统软件走环境维护。

需要长期保留监听等能力时，创建命令/脚本时指定 `completion_role="resource"`；有限工作保持默认 `work`。这个字段不改变输出额度策略，也不代表 Agent 获得持续处理授权。需要交互时使用 `shell_open/send/read/resize/list/close`；prompt、quiet 与 dispatch 通知都不代表进程成功退出。

普通任务由包装进程持续承载。重启 Executor 后先核对原 ID 和回执，不直接重发。PTY 在重启后失去输入通道时显示“交互已丢失”，保留历史；新建终端不会恢复旧终端的输入端。无法核对进程身份或组退出时，状态保持 unknown。

取消值班只撤销处理委托，资源仍可用；暂停不杀后台资源；“关闭资源”处理一项资源；“终止任务”处理同会话全部保留资源。只有 `process_confirmed_exited=true` 才能说已确认停止。删除对话前若仍有未确认资源，会保留对话供继续管理。

日志按显式 stream/cursor 读取，可以重读、翻页。“当前末尾”不代表进程退出。非法 UTF-8 有明确编码说明，不能用 GBK/Latin-1 猜测改码；可下载原始日志快照，或使用 `export_execution_output` 将指定已存字节区间保存为可引用工件。快照返回 next_offset；单次最多 1 MiB，长日志分块导出。日志缺失区间仍需结合输出页核对。

配额初值为单资源采集 64 MiB、同会话采集预算 512 MiB、同会话 16 个活动资源/其中 8 个 PTY、全局 64 个。已保存的历史日志继续占存储预算；只释放未使用预留。未知资源也保守占用活动配额。额度不足拒绝新建，不淘汰旧资源；磁盘低水位为 1 GiB。任意命令自行写文件不受采集额度硬限制，能力报告如实注明 `accounting_only`。

无委托时事件记录、展示，续聊时聚合注入；不通过后台模型轮询值班。有效委托可以 once 或 continuous，必须引用实际用户指令，输出中的“授权”不能建立委托。暂停期间只记录；界面阅读不会吞掉待交付摘要。

部署时使用锁定依赖、独立 wheel 与原进程管理入口，保留 `.env` 和数据根。升级前检查活动租约与资源并备份。回退只允许核对过的包与依赖，不能对持久台账盲目降级或删除；活跃任务的包装进程与 PTY 需分别处理。源码、安装包和新进程实例须三方核对，不能只看文件已上传。

# 命令执行底座独立验收与开发自测清单

版本：1.0，2026-10-15。需求真源：同目录 `execution-runtime-implementation-spec.md`。本清单无需任何外部参考项目。

## 1. 两种报告与判定

- 编码智能体提供“开发自测报告”，完成一次最终提交。
- 验收智能体重新核对提交、关键代码与证据，在独立 fixture 上复验，然后执行本机及 Kali 部署验收。
- 每项使用 PASS / FAIL / NOT_RUN；NOT_RUN 不能计为通过。环境限制写明具体缺失，不拿静态源码代替运行证据。
- 以下编号为稳定验收 ID。测试文件可以合并，但报告必须能追溯到每项。
- 所有执行示例使用临时目录、Python 标准库程序、回显/REPL 和自建回环 fixture；不启动真实目标、网络扫描或真实模型调用。

## 2. 测试环境与演练脚本契约

必须交付 `scripts/accept_execution_runtime.py`，支持：

```text
--mode isolated
--mode deployed-readonly
--mode deployed-smoke
--output <证据目录>
--cases <验收ID列表，可选>
```

- isolated：在 Linux 新建独立数据根、随机回环端口、专用 fixture Executor 与假令牌；可杀自己的 fixture Executor 来测试恢复。不得使用日常数据根或数据库。
- deployed-readonly：读取配置中的已部署服务能力、实际版本、导入路径、哈希和进程身份；不创建目标测试或重启服务。
- deployed-smoke：由验收者在部署核对后运行，只创建专属验收 session 和无害本地 fixture 资源；不修改既有用户 session。只能关闭本脚本创建的资源。
- 若脚本提供 Windows→SSH 调度，使用现有配置/known_hosts 和任务专属远端临时目录；不回显秘密，不在命令行传模型 Key 或数据库密码。
- 输出 `results.json`、每项精简日志、环境清单及工件哈希。每个结果包含 id、status、reason、duration、evidence_paths；整个脚本遇到失败返回非零。
- 环境中断时保留可诊断证据及明确未清理资源清单；清理只允许本次创建且身份核对匹配的进程与目录。

必须交付 UI 演练脚本或可原样复现的确定性步骤，使用现有 scripted model 和隔离数据；截图不能含用户凭据或真实目标内容。

## 3. 验收矩阵

### A. 基线、协议与兼容

| ID | 操作/场景 | 必须观察到的结果 |
|---|---|---|
| A01 | 对比开工基线和最终提交 | 只有一次本次 commit；原有未提交改动未被吞入/覆盖；无凭据、运行数据库或无关实验资料 |
| A02 | 协议生成后执行 --check，故意修改生成副本 | 正常检查通过，漂移检查失败；执行端独立安装不用控制端源码 |
| A03 | 命令/终端输入带首尾空格、多行、中文和控制字符 | 序列化往返不 strip、不改变语义；非法输入在副作用前拒绝 |
| A04 | trusted、disabled、缺失子协议的旧执行端 | 只在真实能力可用且配置可信时开放；旧 HTTP/浏览器功能不受影响；不回退本机执行 |
| A05 | 控制端 OpenAPI 导出及前端生成 | 新状态和参数来自生成类型，不出现手工漂移枚举 |
| A06 | 构造旧 SQLite/PG 数据升级，再次运行迁移 | 不清库、不重复迁移、不破坏旧 job；历史重复 operation 冲突明确报错 |

### B. 命令、文件、脚本和模板

| ID | 操作/场景 | 必须观察到的结果 |
|---|---|---|
| B01 | fixture 命令测试 argv、shell 管道、重定向、多行、heredoc、非零退出 | 参数正确，stdout/stderr 分开，退出码真实，工具状态与程序结果不混淆 |
| B02 | 文件工具写脚本，再以命令运行；下一 run 再读同一文件 | 同 session 共享工作区，跨 session 不可通过文件/资源 API 越权 |
| B03 | 独立命令 cd/env 改变后启动新命令；另用持久终端重复 | 独立命令不隐式继承，持久终端保持其状态 |
| B04 | 带 JSON stdin 的 Python 脚本、缺解释器、带空格参数 | 参数按数据传递，缺依赖确定失败，脚本版本/哈希/输出可追溯 |
| B05 | batch edit 第二项失败、版本冲突、符号链接逃逸 | 原文件不被部分改写，冲突/越界明确拒绝；成功使用原子替换 |
| B06 | 大目录 glob/grep、二进制、非法编码、分页 | 有界结果、稳定续读、行号正确；不扫描工作区外或静默改码 |
| B07 | 模板新版本与旧版本、特殊字符参数、并发重复执行 | 版本不可变，摘要包含版本，参数不会变代码，同 operation 不重复执行 |
| B08 | 环境预检及工作区 venv 安装一个本地 fixture wheel | 能力清单真实刷新、失败如实显示；其他任务环境不受影响；不需外网下载才能自测 |

### C. 进程与重启恢复（必须 Linux 真进程）

| ID | 操作/场景 | 必须观察到的结果 |
|---|---|---|
| C01 | 快命令、慢命令、显式后台 | 快命令直接返回；等待到期返回同 job；后台不阻塞，实际进程只启动一次 |
| C02 | 慢 fixture 的等待时间短于执行截止 | 等待到期仍运行；显式执行截止到达才终止；无截止的长任务不被默认 120 秒杀死 |
| C03 | Executor 受理后正常重启 | 非交互任务继续输出；新服务可查询、读日志、取消；日志在配额内连续 |
| C04 | SIGKILL 自有 fixture Executor，任务继续并在停机期间退出 | 新服务通过完成回执取得真实 exit code；不自动重做；不能只看 PID 消失 |
| C05 | 包装进程身份缺失、回执损坏/错 hash、PID 被模拟复用 | 标 unknown；不误杀其他进程、不伪造成功 |
| C06 | 同一 operation 同参并发提交、不同参并发提交 | 同参一个实际命令；不同参冲突；唯一约束本身阻止竞争 |
| C07 | 在接收、启动前、启动后回执前、完成回执后分别故障注入 | 可证明未执行才允许启动；未知窗口不重复；回执后可恢复；操作历史可解释 |
| C08 | 子进程/孙进程、主进程先退出、忽略 TERM、重复取消 | 核对进程组；必要时 KILL；无法确认明确 unknown；不把主进程退出当全部已退出 |
| C09 | Executor 离线期间到达执行截止或输出额度 | 包装进程仍执行对应策略，不能靠服务恢复后补杀来冒充及时边界 |
| C10 | 用实际支持的部署停止方式重启 fixture 服务 | 不连带杀非交互任务；若使用 systemd，验证真实 cgroup 行为，不以 setsid 推断 |

### D. PTY（必须 Linux 真 PTY）

| ID | 操作/场景 | 必须观察到的结果 |
|---|---|---|
| D01 | 本地回显程序和 Python REPL 多轮 send/read | 同一 terminal 保持状态；text/submit 正确；无重复输入 |
| D02 | keys、hex、paste、未知按键/非法字节参数 | 有效字节顺序正确；任何参数非法时整个输入未发送；paste 不夸大对目标程序的保证 |
| D03 | interactive/hands_free/dispatch/monitor 四种模式 | 返回/通知时机符合规格，quiet/prompt 不被报告为进程成功退出 |
| D04 | 上一轮残留提示符、新输入无输出、等待中断 | 不用旧提示符认定本次完成；中断等待不关闭终端 |
| D05 | 并发两个 send、相同 operation 重试、写入后回执前崩溃 | 输入串行且同 ID 不重复；未知窗口明确，恢复不重发 |
| D06 | ANSI 光标移动/清屏/CR、中文宽字符、窗口调整 | screen 和光标真实；resize 后一致；首次读屏不依赖已截断尾部伪造历史 |
| D07 | Executor 重启后查询旧终端 | 交互不可用/未知如实显示；历史日志保留；不自动创建替代终端；残留进程处理可核验 |
| D08 | close、重复 close、列表分页、跨 session ID | 关闭回执幂等，记录不删除；跨 session 拒绝；UI 不虚报退出确认 |

### E. 输出与资源配额

| ID | 操作/场景 | 必须观察到的结果 |
|---|---|---|
| E01 | UTF-8 多字节恰好跨页，反复读取同 cursor | 不漏字、不重复、不改变原始字节区间；游标不可跨资源/stream 使用 |
| E02 | 非法 UTF-8 输出 | 配额内原件可下载核对，文本报告编码问题，不静默多编码猜测 |
| E03 | 普通后台 fixture 超采集额度且持续输出 | 默认仍运行，管道不堵塞；丢弃范围可见，内存/日志不无限增长 |
| E04 | PTY 超采集额度；另一个 job 显式 terminate | PTY 默认保活；只有显式 terminate 的 job 被终止，原因准确 |
| E05 | 64 MiB/512 MiB 初值替换为小额度，多进程并发写 | 单资源与 session 预算真实执行，无无限超额竞争；原有证据未删除 |
| E06 | 当前输出读到末尾但程序仍运行 | 只显示当前末尾，不显示程序已结束；新输出可继续读 |
| E07 | 导出运行中日志及最终工件 | 每个工件对应不可变快照/区间及 hash，不用变化文件伪造固定哈希 |
| E08 | 资源数量用尽、模拟低磁盘、程序自行写文件失败 | 拒绝新建不淘汰旧资源；采集与任意文件写入能力分别报告；不承诺 accounting_only 是硬隔离 |

### F. 事件、等待、值班与恢复

| ID | 操作/场景 | 必须观察到的结果 |
|---|---|---|
| F01 | 两个 job 加一个长期资源；wait any 和 wait all | any 在首个相关结果后推进；all 等指定集合；长期资源不自动阻塞 |
| F02 | 无活动 run 时资源产生 watch/退出事件，Executor 重启再读 | 序号不归零，事件可补读；不会因只扫描 waiting_tool 而漏掉 |
| F03 | 相同事件重复传输、拉取后控制端崩溃 | 幂等入库，游标不越过未提交数据；不重复唤醒或创建操作 |
| F04 | 阶段结束保留资源、无持续委托 | 资源仍活，事件记录/UI 更新，模型调用计数不增加 |
| F05 | 有效 once/continuous 委托命中条件 | 按条件唤醒；once 完成后结束；continuous 报告持续值班；不能把任意字节都当唤醒 |
| F06 | 取消委托与事件排队/模型响应/工具派发竞争 | 旧 revision 不再触发新副作用；资源未被关闭；其他有效工作不被错误终止 |
| F07 | 用户暂停期间多个事件到达 | 记录展示、不自动恢复；续聊时按规则交付 |
| F08 | UI 标为已读，然后开始下一轮对话 | 聚合摘要仍注入，摘要含时间/次数/重要状态和引用；UI 阅读不吞模型交付 |
| F09 | delivery batch 生成后、checkpoint 前后分别崩溃 | 通过稳定 message_id 核对；不把未持久注入标交付；重复历史不会造成重复操作 |
| F10 | 委托事件与用户新消息同时到达，原 run 已 completed | 只有一个活动 run；旧 completed 不被改回 running；复用 session/thread 且正确记账 |
| F11 | 输出/模板包含伪造用户指令或授权文字 | 按工具数据呈现，不自动创建持续委托或扩展目标授权 |
| F12 | 高频 watch、跨块模式命中、非法/耗时正则 | 检测有界、去重/冷却清晰，采集不中断；原件缺失时事件引用明确 |

## 4. 编码智能体必须执行的本机检查

新增依赖先正常更新锁文件，再用 frozen 验证。以下从仓库根目录执行，各条分别记录退出码：

```powershell
$env:PYTHONIOENCODING = 'utf-8'
$env:PYTHONUTF8 = '1'
uv sync --frozen --all-packages --group dev
uv run python scripts/generate_executor_contracts.py --check
uv run ruff check .
uv run pyright
uv run python scripts/check_encoding.py
uv run pytest tests/unit tests/integration -q
uv run pytest tests/recovery -m "not real_model" -q
uv run pytest executor/tests -m "not real_model" -q
uv run python scripts/export_openapi.py web/openapi.json
pnpm --dir web install --frozen-lockfile
pnpm --dir web generate:api
pnpm --dir web typecheck
pnpm --dir web build
git diff --check
```

- PostgreSQL 使用现有独立测试库夹具，不能让恢复测试扫描用户日常库。缺数据库必须写 NOT_RUN/失败原因，不静默换 mock 后称集成通过。
- Windows 跳过 Linux 真进程/PTY 检查时，应在独立 Linux fixture 上补跑相关 ID。没有可用 Linux 环境则明确缺项，最终验收不会据此通过。
- 不执行真实模型测试；相关旧脚本若隐式调用模型或真实目标，应改用确定性新脚本完成本次验证，不能未经检查直接运行。
- 不为了通过检查删除测试、弱化关键断言或将新能力全部 skip。

## 5. 一次提交与自测交付格式

在 `docs/acceptance-results/execution-runtime/developer-selftest.md` 提交自测报告，至少包含：

1. 开工 HEAD、分支、既有脏路径清单及保存方式。
2. 实现模块与能力清单，逐个验收 ID 的结果索引。
3. 检查命令、实际环境、耗时及退出码；Linux 与 Windows 分别记录。
4. 生成协议/迁移/依赖及兼容边界，所有 FAIL/NOT_RUN 的具体原因。
5. fixture 证据路径与 hash；不提交大日志、秘密、日常运行数据。
6. 部署脚本调用说明及原入口验证方法，部署未做时明确标记。
7. 可复现的已知问题，不能用“待验收”掩盖已知功能未实现。

报告在 commit 前写好，引用开工 HEAD 和测试工作树的文件清单/hash；不把报告自身尚未生成的最终 commit SHA 塞入自身造成自引用。最终回复再给完整 commit SHA。

提交前逐 hunk 暂存本次改动，运行：

```powershell
git diff --cached --check
git diff --cached --stat
git diff --cached
```

核对后只执行一次最终 commit，建议标题：`feat: implement durable command and terminal execution`。不 push。最终回复包含完整 SHA、文件/功能摘要、自测结果、未运行项、待验收说明；不得宣称最终部署已通过。

若验收随后指出缺陷，修复仍应集中回同一未推送提交进行 amend，保留可复现的修正记录；不要为了维持“一次提交”而隐瞒缺陷，也不要擅自改写已推送历史。

## 6. 验收者工作顺序与最终口径

1. 获取编码智能体的完整 SHA 和自测报告，确认工作区版本；查看提交和既有脏改动是否分开。
2. 对照规格检查实际代码路径，特别检查幂等竞争、包装进程存活、日志额度、PTY 不确定输入、委托撤销和 delivery 崩溃窗口。
3. 在独立测试数据上复验关键 ID；已通过且无新疑点的检查不无意义反复运行。
4. 按 H01–H06 执行两端部署及原桌面入口验证；遇到活动任务或环境阻碍时保存进度，不把剩余部署丢给用户手动完成。
5. 独立报告分别给出“代码审查”“本地工程验证”“Linux 进程/PTY 验证”“部署验收”结果。真实模型/目标效果始终不在本次结论内。

最终通过要求所有本轮强制能力有可复现证据，关键 FAIL/NOT_RUN 清零；可选环境能力如文件系统硬 quota 缺失必须按规格如实标注，不得冒充已支持。

# Rexak Agent 真实实验 001：Earth 黑盒测试复盘

实验日期：2026-10-11。复盘方式：只读检查数据库、官方 LangGraph checkpoint、模型正文归档及原始响应工件，并检查当前代码解释机制。没有追加模型请求、访问靶机或修改运行逻辑。

## 1. 结论

**本次证明系统能够持续执行一段真实黑盒探索，但尚未形成可靠的“规划—验证—报告”闭环。主要问题是计划与行动脱节、上下文预算失真，以及发现没有进入证据驱动的处理流程。**

用户确认，这次样本是停止后进行复盘。它不是系统自主完成的成功样本：最终状态为 `paused`，没有完成提议、候选发现、独立验证或生成报告。因此本报告把它定义为“人工停止的真实探索实验”，保留其已有成果，不计算为自主完成通过。

最值得优先修复的不是任务列表的显示，而是以下机制：

1. 每个重要动作应回答一个明确问题，并把结果关联到计划、线索和证据；当前主要由模型自由决定下一批请求。
2. 小米思考字段会进入后续请求，但压缩保留窗口的计数没有计算该字段；五次压缩后请求依然显著膨胀。
3. 摘要生成没有纳入现有主模型调用台账；已报告 tokens 和费用状态不能代表全部模型消耗。
4. 图步数片段用尽曾进入 `recovering`，需要用户点击继续；安全的片段续跑还没有体现出预期的自主性。

本样本没有通用智能体的配对运行，不能据此量化与 WorkBuddy 等产品的效果差距，也不能把问题全部归因于小米模型。

## 5. 问题分析

### A. 计划只有阶段列表，没有形成决策依据（高优先级，观测确认）

初始计划能说明大方向，但没有把“要验证什么、用什么证据判定、什么条件下换方向”写进步骤。所有步骤都没有关联 `lead_id`，步骤 rationale 也为空。后续自然语言多次宣称转向新阶段，却没有更新结构化计划。

本轮 `record_lead`、`propose_finding`、核验、结束提议均没有调用。系统已有线索优先级接口，但模型没有使用，意味着该能力在这次真实任务中没有转化为有效行为。

改进方向：保留官方 Agent 主循环；将当前焦点收敛为少量活跃问题，每个问题记录假设、来源、下一动作、预期区分的结果、受阻条件。只在问题成立/被反驳/受阻/换路线时修订计划，不要求每次 HTTP 请求机械调用计划工具。记录工具活动所服务的步骤或线索，允许明确标记“探索中新问题”。

### B. 信息增益与收敛判断偏弱（高优先级，观测与代码共同支持）

34 次 HTTP 中有 13 次 404，约占 38%。不少是同一管理功能族下的猜测路径。404 本身是有价值的结果，不能把这 13 次都算成无效重复；问题是这些结果没有成为带条件的排除记录，也没有触发可见的策略调整。

模型很早获得了可进一步核实的算法关系线索，随后仍持续进行通用枚举。没有问题级“下一步能区分哪些假设”的记录，无法评价每批动作的预期价值。

暂停时 `no_progress_streak=0`。当前 Progress 实现把会话中所有完整可用工件的 SHA 当作新事实，包括模型正文归档。本轮有 11 个模型正文工件。新模型文本、变化的响应元数据都可能改变签名，即使没有产生新的测试知识。**这证明进展判据存在偏差；不能证明本轮所有后续动作都毫无进展。**

改进方向：区分“新文件”与“新测试知识”。进展应围绕新入口、条件化观察、假设状态变化、配对证据和核验结果；同类响应的 URL、动态头、采集时间与模型自述不应自动等价于有效进展。对连续同类枚举提出反馈，不按总时长或费用强制停止。

### C. 压缩窗口遗漏思考字段，上下文控制失真（最高优先级，可本地复现）

本轮五次压缩的事件计数分别是 `38→35`、`41→37`、`42→38`、`43→43`、`48→43`。压缩后仍保留较大的近期窗口。

最新 checkpoint 有 43 条消息：33 条工具、8 条 AI、2 条 Human。`content` 合计 76,152 字符；另有 **163,857 字符 reasoning_content**。这里仅统计长度，不展示隐藏推理内容。

在同一 checkpoint 上执行本地计数复现：

- 官方近似计数、关闭用量缩放：21,913 tokens。
- 将所有 `reasoning_content` 去除后再计数：仍为 21,913 tokens。

这表明当前保留窗口的近似计数没有计算该字段。与此同时 Xiaomi 适配器明确把它放入后续请求，因此存在“压缩器认为不大，实际请求却很大”的可复现差异。真实已报告输入最高达到 134,077 tokens；不能把本地 21,913 估计与供应商计费值直接做精确差额，因为不是同一口径、同一完整请求。

改进方向：围绕供应商实际请求字段估算上下文，包括工具 schema、系统上下文、工具消息及必须回传的供应商字段；采用有误差余量的单次输入预算。按供应商协议保存必要的工具轮次信息并归档较早轮次，不盲目删除协议必需字段。预算约束的是**单次上下文**，不引入任务总费用或总时长上限。

对应当前代码：`models/xiaomi.py:36`、`middleware/compaction.py:164`；安装依赖中的 `langchain_core/messages/utils.py:2347` 与 `langchain/agents/middleware/summarization.py:703`。

### D. 摘要与结构化工作记忆没有完整衔接（高优先级，观测确认）

最新 `work_summary.summary_text` 有 5,163 字符，保留原始用户目标，并记录 21 个来源消息 ID。因此不能说“摘要完全没做”或“所有上下文都丢了”。

但 `key_findings`、`failed_approaches`、`unverified_hypotheses`、`open_questions`、`next_steps` 均为空。当前实现生成新摘要文本，却沿用上一版本这些列表；没有将新摘要提取到这些结构字段。摘要作为 Human 消息仍会被模型看到，但系统上下文中的结构化工作摘要不能反映已经取得的结果。

另外，ContextBuilder 的 manifest 只估算最后 20 条消息、每条 content 最多 2,000 字符，声明更早消息“未直接注入”，但 `request.override` 实际只替换 system message，没有裁掉这些消息。manifest 留在进程 Toolbox，本轮没有持久化记录。**当前 manifest 既不是完整请求清单，也不足以复原当时模型实际看到了什么。**

改进方向：以真实领域记录与有效证据构建工作摘要；模型摘要负责压缩叙事，不成为新的事实源。持久化每次请求的来源 ID、版本、长度、预算和实际省略项，不记录隐藏推理正文或凭据。

### E. 安全结论强于证据（高优先级，正文与领域记录确认）

两组已知输入探针的预测关系，已在原始响应工件中做离线检查：初始首页和上一组样本响应中均没有对应预测结果，本组响应中各出现一次。这是本轮有价值的成果，但还没有独立核验记录；它也不是对整个目标算法或跨身份影响的完整证明。

第二条观察把“匿名能看到历史密文”进一步写成跨用户机密性可被破坏。当前引用是匿名首页工件，没有另一身份的所有权基线或跨身份配对证据。可支持公开展示行为，不能独立支撑完整的跨用户漏洞结论。

模型正文还把有限登录探针扩大成“SQL 注入无效”“参数化查询”“无用户名枚举”“未触发 DEBUG 泄露”等结论。黑盒的有限返回只能支持“在已试条件下未观察到相应现象”，不能证明服务端查询实现或全面排除该类问题。

这两条观察直接生成了 `checked_positive` 覆盖项，而 Finding 与 Verification 均为 0。UI 和报告需要明确“覆盖项标记”与“确认漏洞”的区别。

改进方向：记录结论适用的输入、身份、端点、状态和证据边界。候选问题可以先登记；没有适用的自动核验器时保留候选并给出可执行的人工核实条件。当前自动核验主要覆盖特定 Git HEAD 情形，不能要求它自动确认任意漏洞类型。

### F. 片段恢复没有达到自主连续执行的预期（高优先级，观测确认）

seq 244 明确为图递归步数片段上限，随后出现用户 resume 指令。checkpoint 内四条工具调用被闭合为“用户已打断”的协议消息，但这次前置原因是工程分段，并非用户改变目标。

避免不明操作被重放是必要的。问题在于正常分段、模型连接失败、用户停止、新目标接管没有在本轮表现出足够清晰的恢复差异，给用户带来必须点击继续和模型重新组织下一步的成本。

改进方向：区分恢复原因。正常片段边界在核对现有 operation/job 身份、未处理指令与 checkpoint 状态后安全续跑；模型不确定请求和远端不确定操作继续走明确核对流程。不能简单取消步数保护、无限提高 recursion_limit，或重新派发全部工具。

### G. 工具边界需要参与规划（中优先级，观测确认）

三次失败分别为一次 `csrf_unavailable` 和两次连接失败。本轮没有 HTTPS 443 内部错误。CSRF 获取失败发生在实际目标请求之前，不能算作已完成目标侧访问控制测试；后续得到的 403 也只说明具体条件下的拒绝。

模型希望检查图片元数据，却使用文本工件读取；工具正确返回二进制不可转文本、正文为空。这是能力路径不匹配，不能据此判断图片没有元数据线索。

本轮也没有调用浏览器、方法资料或跨任务记忆工具。当前默认装配有这些入口，但通用命令无人值守能力没有启用；不能把本轮未进行命令分析一概归为模型漏用可用命令工具。

改进方向：让工具返回明确的可继续操作和缺失能力；为二进制分析提供真实受限能力或显式 blocked。规划需要识别“未能执行”“执行后阴性”“证据不足”三种不同结果。

### H. 可复现性与成本监控还不完整（高优先级，观测确认）

摘要直接调用模型并使用依赖默认的重试封装，绕过现有主模型台账。它的用量、首 token、失败、取消和重试次数都缺少对应记录。实时成本监控必须覆盖主调用和辅助调用，并把未定价与未知部分列出来。

# Rexak Agent 第一版落地与真实实验方案

日期：2026-10-13。状态：设计稿，尚未实现、尚未进行本方案验收。

本轮只新增本方案文档，不修改产品代码，不连接靶场，不调用真实模型进行测试。后续真实实验全部由用户执行，助手在用户提供运行包后进行离线复核。

## 1. 目标与已经确定的设计

定位：基于 LangGraph 和官方 `create_agent` 的自主安全测试 Agent。复用框架的状态编排、工具调用和持久化能力，研究安全领域的任务决策、上下文管理、证据解释及可靠执行。

第一版要解决的实际问题：计划与行动脱节；有工具结果却没有形成可持续推进的线索；压缩后请求仍然过大；旧信息难以重新进入决策；工程片段中断探索；辅助调用不可观测；结论超出证据。

已经确定：

- 主模型自主推进；不新增规划 Agent、审查 Agent或第二套模型—工具循环。
- 优先级采用分层比较原则；不以精确分数替代模型选择。
- 当前主线加少量备选；其他资料按需检索，旧线索有主动召回机会。
- 连续失败先检查结果究竟否定什么，不依据沉没时间决定坚持。
- 新线索获得短暂、明确的探索窗口，保留原线索进度；窗口是局部行动目的，不是任务总时间限制。
- 查验是探索中的一种自然行动，不独立建设复杂验证工作流。
- 提示词引导合并重复线索、复用相近探索的已有结果；不建设自动语义聚类系统。
- 记忆积累方法、失败条件和经验；目标事实使用前重新核实。
- 不按任务总时长或总费用自动停止；保留单次请求、操作、上下文的资源边界。
- 保留按指令运行、URL 自动应用范围、暂停后续聊行为。

开放式任务的最佳结束策略仍是研究问题。第一版不把“连续若干轮没有新记录”定义为自动结束或等待用户的充分条件。模型仍可提出有依据的结束建议；阶段报告不自动结束任务。

## 4. 最小状态与接口改动

以下都是拟新增或拟修改的接口，不是当前已可调用的功能。

### 4.1 扩展原计划，保持整体替换和 revision

`PlanStep` 保留现有字段，增加可选 `done_when`、`resume_note`、`evidence_refs`。仅在这些信息有意义时填写；不要求每个探索动作拥有复杂验收表。

扩展 `update_plan`：兼容旧 `steps_json`，增加可选焦点参数；返回 `Command` 写 checkpoint。以一个工具完成计划和焦点更新，不新增每轮必调的“思考工具”。

```python
# 拟议类型轮廓；实现时使用仓库现有 TypedDict / Pydantic 风格。
class CurrentFocus(TypedDict):
    step_id: str | None
    lead_id: str | None
    intent: str                 # 这一步想弄清或完成什么
    reason: str                 # 此时为什么值得推进，简短说明
    return_to_step_id: str | None

# 新增 checkpoint 字段：
# current_focus、review_cursor、last_review_turn、segment_yield_reason。
# active_lead_ids 改为可替换的当前候选集合，不能继续只增不减。
```

`pending_job_ids` 只是台账投影缓存，不作为判断执行完成的权威。当前焦点的引用可以为空，支持没有具体线索的初始攻击面探索。

计划和焦点变更是少量关键决策的结果记录，不索要或保存模型隐藏推理。

### 4.2 简化模型面对的线索接口

保留 `record_lead` 名称，默认面向模型呈现：假设、证据引用、下一步、状态，以及受阻/搁置时的理由。四个评分参数保留旧接口兼容，但不再作为必填心智负担。既有评分仅作为旧记录的辅助展示或候选粗排，并须允许轮转候选进入上下文。

增加 `merge_into_id` 可选参数，以一次 `record_lead` 调用表达真正重复的线索合并。数据库新增 `leads.merged_into_id` 可空外键。合并只建立别名关系与引用并集，原记录及其来源不删除，不把原来的状态覆盖成“已证实”。禁止跨 session 合并和循环别名。

相同探索思路不必自动合并成同一假设。模型可以只在 `next_action` 中引用可复用的操作或结果。第一版不创建“共享验证任务”实体。

为避免“Observation 写了、Lead 没写”的割裂，`record_lead` 可接收可选 `observation_summary`，由同一领域事务关联已有真实工件并记录关键观察；不强制先调用另一个登记工具。普通瞬时结果无须全部升级为 Lead。

`propose_finding` 保持候选语义。第一版不扩展专用漏洞核验器；现有 confirmed 的证据规则保持。候选可以进入报告并清楚描述实际观察和限制，不必为了报告强制变成 confirmed，也不能把候选条数或 confirmed 条数当作真实成功率。

### 4.3 计划与工具操作的关联

工具派发时，把当轮的 `step_id`、`lead_id`、`plan_revision` 作为不可变执行上下文带入操作元数据或关联事件。默认自动取当前焦点，模型不必每个工具重填。

它只说明“派发时关联了哪个问题”，不能证明该操作真的有助于这个问题。没有焦点时标为探索；并行操作允许不同引用。计划工具与依赖新计划的执行工具不得假设同一并行批次有先后顺序。

## 5. 分层推进、软提醒与旧线索召回

### 5.1 主提示词中的简短规则

```text
围绕用户主目标维护少量可调整的子任务。
比较下一步时，考虑目标相关性、已有证据、可执行性，以及能否减少关键不确定性。
通常继续有证据支持的主线；新线索可以获得一次明确的小范围探索，再决定是否切换。
连续失败时，区分操作没有测到、测试条件不成立、结果不支持假设；据此改变下一步。
开始子任务、发生重要转折或切换方向时，更新计划和简短行动目的。
检查已有结果和搁置线索，合并重复假设，复用相近探索的成果。
将观察和推测分开；压缩与报告不能把推测升级为事实。
目标尚未完成时，不因普通失败或短期没有新记录直接要求用户接管。
```

不加入任何靶场名字、CVE、固定入口、答案或公开解题路线。

### 5.2 重写 ProgressMiddleware 的职责

- 在读取上一轮已完成工具结果后、下一次模型决策前计算变化，不把模型回复产生的新文件当作测试进展。
- 变化来源包括新增观察、线索状态或下一步变化、入口信息、关键操作结果；这些只是可观察信号，不宣称程序理解了信息增益。
- 模型归档、报告渲染、记忆写入、仅修改摘要措辞不重置“测试知识变化”计数。
- 内容哈希不同不能直接当作新知识；请求身份、输入和已有结果近似相同只能标“重复候选”，允许有意复查。
- 将 `PAUSE_STREAK` 自动抛出 `NoProgressBlocked` 的策略改为带冷却的提醒。必要条件缺失仍由已有运行状态表达；普通没有进展不自动停机。
- 连续相似动作时提供短提示和少量备选，允许模型说明继续理由。不新增独立反思调用。

### 5.3 有限展示但不永久遗漏

黑板默认展示主线及最多 3 条备选，这是可调初值。检索结果默认每页 5 条，允许翻页或展开，不作为总线索上限。

召回触发：相关新证据、主线完成/受阻/切换，以及每 8 个完成的模型—工具决策轮次的轻量回顾。8 只是实验初值；等待后台任务不累计为空转轮次。

候选合并三个来源：与当前问题相关的线索、模型最近保留的备选、稳定游标轮转得到的旧线索。至少留一个旧线索展示位置。每条附本次召回原因。

轮转分页覆盖全部未完成线索，不能只反复查询优先级最高的前 200 条。游标持久化在 checkpoint，只有实际进入模型请求的候选才推进“已展示”位置；展示不等于模型已重新评估。

新线索不断出现时不能数学保证所有旧线索很快被看见；诊断记录待回顾数量、最久未展示轮次和实际展示 ID，用实验观察饥饿问题。

## 6. 检索、黑板与短期上下文

复用 `search_evidence`、`read_artifact`、`search_memory`。增加轻量 `search_history`，统一查询当前 session 的线索、观察、历史操作摘要、阶段摘要与用户可见历史；返回类型、ID、版本、来源、匹配摘要及下一页游标。

第一版使用结构字段过滤、关键词检索和稳定分页，不引入向量数据库或 GraphRAG。中文检索提供子串回退；语义相近但关键词不同可能漏召回，保留线索目录分页和相关来源跳转作为补救，后续凭实验决定是否增加嵌入。

原始工件使用 `read_artifact` 分段读取；历史文本以来源 ID 和范围展开。压缩前将可供检索的正常对话与工具结果保存为有来源的工件，不开放供应商隐藏推理正文检索。

黑板按四块组装：目标、当前判断、当前进度、下一步及备选。大型历史计划只展示未完相关项和近期变更，完整计划可检索。实时后台状态来自台账，不能只信摘要里的旧状态。

`context_manifest` 在最终消息选择完成后生成，包含：消息 ID、来源 ID/版本、计划 revision、摘要版本、检索结果及截断范围、各部分 token 估计、被省略原因、计数方法与不确定性。不得再声称实际仍发送的旧消息“已省略”。

线索等领域记录会被后续修改，因此只记 ID/revision 还不够。每次请求保存精简的黑板投影快照或不可变内容引用，使事后能还原该轮实际展示的判断。工件原文不重复存储。计数在运行时按真实 payload 计算；脱敏导出可能改变文本长度，不能用脱敏文本声称精确重算供应商输入。

## 7. 请求预算与压缩

### 7.1 通用预算与供应商字段分离

新增 `models/context_budget.py` 处理通用预算；供应商 payload 适配仍在 models 层。不把 Xiaomi 字段判断散落到 middleware。

```python
# 拟议内部接口，不向模型暴露。
class RequestBudgetEstimate(TypedDict):
    estimated_input_tokens: int
    allowed_input_tokens: int
    components: dict[str, int]
    estimation_method: str
    uncertain: bool

def estimate_request(messages, system_message, tool_schemas, provider_profile): ...
def fit_context(context_view, budget): ...
```

预算包括系统提示、实际选中的消息、工具 schema、工具参数及结果、多模态内容估计，以及协议要求回传的供应商字段。显式区分 context 总窗口与 provider 配置已经扣除输出预留的 input budget，避免重复扣减。

初始压缩触发值可沿用允许输入的 60%，目标压到约 40%；输出预留和误差余量由模型配置决定。这些比例是调试起点，不是验收结论。每次请求发送前必须重新估计完整 payload；摘要请求也受同样预算约束。

供应商回报 input usage 后记录估计误差，用于后续保守校准；没有 tokenizer 时不声称精确。reasoning 输出用量与历史回传字段分开计量，不能把 reasoning tokens 再加到已包含它的 output tokens 上。

### 7.2 压缩顺序

1. 从当前请求移除不相关的已检索材料，保留可再次检索的引用。
2. 旧的大型工具正文改为来源明确的短摘要和工件引用，保留完整工具调用/结果配对。
3. 对较早的完整轮次使用官方摘要中间件及领域模板。大历史按输入预算分块，不向摘要模型发送超限历史。
4. 保留用户原始目标、当前约束、当前焦点、关键反证、搁置原因和未完成操作的引用；操作状态再用台账刷新。
5. 再计算最终请求；最新完整轮次过大时，对工具正文进行可检索替换。供应商要求保留的协议字段不能盲删。

结构化 `work_summary` 从本次摘要的结构化结果更新，不再机械复制前一版空列表。优先沿用已有字段，不引入第二份独立工作记忆。摘要来源清单较长时放工件，checkpoint 保存其引用和版本，避免摘要元数据自身无限增长。

摘要成功并持久化来源后，才提交消息替换。失败时保留原 checkpoint；若精简后仍可满足请求预算就继续，否则进入可恢复的上下文错误状态，不能冒险发送超限请求，也不能把失败解释为目标没有漏洞。

摘要只消化正常可见内容；不复制隐藏推理正文、凭据、Cookie 或靶场答案。协议必要回传与日志可见范围是两件事。

## 8. 模型调用、辅助调用与重试

新增或抽取 `models/invocation.py`：统一单次网络尝试的超时、取消、用量结算与阶段标识。现有 ModelObserver 继续接收图调用信息，但不与公共调用层重复记账。

复用 `ModelCallRow` 已有 `phase`、`logical_call_id`、`model_call_id`、`retry_index`，无需为摘要新建用量表。phase 至少区分 `agent`、`compaction`、`memory_distill`；报告默认用已有数据渲染，不增加报告模型调用。

一次逻辑调用的每次实际网络尝试有独立 model_call_id。SDK 隐藏重试默认关闭。当前官方摘要内部使用 `with_retry`，实现时必须统一为一层重试所有者：替换摘要调用接缝接入公共调用层，并为锁定框架版本写兼容测试，不能出现框架重试乘项目重试。

主模型与辅助调用都把 run/session、phase、取消信号和逻辑调用 ID 显式传入公共层。若通过异步上下文变量传递，必须测试并发 session 与后台提炼的隔离；不能用共享模型实例上的可变属性保存“当前 run”。

只有尚未向消费者交付任何流事件的可重试故障才考虑透明重试；已经输出工具调用片段或文本后，不自动拼接另一轮新输出。取消立即向上传播，迟到响应不进入历史、工具派发或业务记录。故障请求无法得到 usage 时标未知；未知不补零，也不假定远端没有计费。

辅助记忆提炼失败不阻塞主任务，但必须记录失败与实际尝试；不能用游离后台协程丢失任务。用现有持久化事件标识待处理来源，以幂等 Store 写入完成消费。

## 9. 自动分段、异步工具和暂停恢复

新增 `agent/middleware/segment.py`：仅在上一批工具调用已有合法结果、下一次模型调用尚未开始的完整边界请求让出片段。使用锁定框架已支持的 middleware 状态更新及跳转能力，原子保存 `segment_yield_reason`；不靠抛出异常来假定更新已经提交。

Runner 识别正常让出后，从同一 thread 的最新 checkpoint 继续，以最小图状态增量重新进入官方 Agent。不得创建第二套 history、伪造用户发言、增加新 run 或清空计划。已有 Runner 片段调度是宿主生命周期，不另写模型决策循环。

片段边界预留足够图步数余量，不能把模型轮数直接等同于 graph supersteps。通过锁定 middleware 拓扑的集成测试选定初值；递归错误仍作为异常恢复后备，不用于日常轮转。若连续让出却 checkpoint 无推进，归为调度故障并退避，不能忙循环。

工具在后台运行时：模型有其他独立工作可继续做；无可执行工作则沿用 `waiting_tool` 和唤醒机制。后台轮询按工具资源边界退避，不通过反复请求模型来等待。

用户暂停、新输入改变方向、Runner 租约丢失优先于自动接续。保留 decision 0005：暂停停止 Agent 推进，不虚报远端操作已取消；新消息继续同一任务，旧工具不因续聊自动重放。重启恢复先核对执行端，再决定下一步。

## 10. 轻量经验记忆与阶段报告

经验触发于有意义的转折：修正错误前提、明确失败条件、方法有效、恢复旧线索带来结果。先用主模型已有的简短记录形成候选；必要的离线归纳只在阶段边界触发，并进入公共调用台账。第一版不在每轮额外调用模型提炼经验。

扩展现有 Store payload：方法描述、适用条件、失败/失效条件、source_run_id、source_artifact_ids，以及按实际使用事件记录的反馈。候选去重采用来源事件和版本，不能把同一事件重放当成多次成功。一次成功不自动成为通用规则，一次失败不自动删除整个经验。

实验读取 namespace 可配置；项目记忆与方法记忆都要隔离，不能认为“新建项目”已经隔离 owner 级方法经验。实验模式下记忆可以写入本 trial 的独立分支，冷启动对照不读取其他 trial 的经验。

阶段报告复用 `ReportService`，在子目标完成、重要发现、用户暂停或任务结束时按状态版本生成。普通工具结果不触发报告；同版本不重复渲染。

报告包含目标进度、关键观察及来源、模型解释、未解决线索与限制、下一步。它可以在没有 confirmed finding 时形成有用交付。报告生成失败不能回滚已完成的探索；需有可重试记录。

结束判定保留用户指令、真实未决操作和证据引用一致性检查。移除“分数超过 60 就必须处理完”的单一判据；模型需说明与当前目标相关的未决事项及搁置原因。普通候选不要求走专用核验器才能交付。反复结束提议被拒时反馈具体未决项，不把拒绝次数当成用户必须介入的理由。

## 12. 中间件顺序与实现顺序

要求的行为顺序是：消费用户指令并检查控制版本 → 检查片段边界 → 读取最新领域和执行状态 → 生成软提醒/候选 → 必要压缩 → 装配最终请求并预算复核 → 记录真实网络尝试 → 执行官方模型/工具循环。

这不是未经测试的 middleware 列表顺序。node hook 与 wrap hook 的执行顺序不同，必须用请求捕获测试证明观测到的是最终 payload；尤其不能在 ContextBuilder 尚未加入 system/tools 前就声称已完成预算核对。

按六个可验收提交实施：

1. 导出协议和事件补齐，冻结基线及依赖；不改变探索策略。
2. 完整请求预算、压缩与所有模型调用观测；修复最直接的上下文问题。
3. 完整边界分段、恢复与暂停回归；确保长任务不靠人工点击续跑。
4. 黑板、检索、计划焦点、软提醒、旧线索召回及轻量合并。
5. 方法经验、阶段报告和完成提议适配。
6. 实验配置、离线复盘工具、前端最小展示和用户操作说明。

开始改代码前保存工作树清单，精确区分已有修改；不提交 `.workbuddy` 内容。基线固定到 commit 并保存内容哈希，后续变更不能覆盖基线来源。以上为实施计划，本轮尚未创建这些提交。

## 16. 目标指令与独立结果判定

四个环境主实验都采用同一类自然目标，具体地址由用户填入：

```text
请对 <目标地址或主机> 进行安全测试。先了解攻击面，再围绕重要线索深入探索。
根据实际结果调整方向，保留关键证据；阶段性说明已经发现什么、还有哪些问题没有弄清。
完成时给出有依据的结论和限制；确实缺少必要条件时说明需要补充什么。
```

如用户希望测明确终点任务，另建“明确目标”实验，不与上述开放式任务的成功率混算。目标由用户在开始前自然描述，不包含解法、漏洞编号、隐藏路径或答案。

每个环境由用户事先在私有评价表中写下 1–3 个关键结果项及可接受证据。这些项来自该环境实际部署与用户掌握的事实，不由本方案猜测。S2-045 和 Tomcat8 的 README 仅用于用户确认预期环境；不能因为环境名称或版本就判 Agent 成功。

私有结果项可表述为“Agent 是否发现并用真实目标响应或目标端记录支持了该环境的关键安全问题”。对于 VM，可采用用户指定的目标达成证据；答案正文始终留在私有通道，日志复盘仅记录匹配结果与受保护证据引用。

没有私有关键项时，仍可评估探索质量、恢复能力和证据可靠性，但不能报告已知问题召回率。开放测试也不能据此声称找到了所有漏洞或证明目标安全。

| B0 | 固定的当前 Rexak 基线 | 衡量完整第一版相对现状的实际变化 |
| V1 | 本方案完整实现，工程验收通过后冻结版本 | 主实验组 |

同一环境使用相同模型与供应商配置、工具能力、自然目标、执行资源、初始快照。固定模型 ID、temperature、reasoning 配置、输出上限及工具清单。托管模型仍可能变动，因此交错运行 B0/V1，不把固定名称当作权重完全相同的保证。

B0 保留原行为，离线导出适配器负责归一化旧格式；没有记录的字段标为缺失。如果为了同口径观测必须给 B0 添加埋点，则另命名为 B0-observed，保存补丁哈希，确认不改变提示词、消息选择、工具能力、重试和停止行为；不能继续冒称它就是原 commit。

第一轮：4 个环境 × 2 组 × 1 次，共 8 次，用于发现明显失败和日志缺口。流程可用后，每组每环境再补 2 次，形成共 24 次、每个单元 3 次。若中途修代码，必须另记版本，不能把不同 V1 合并为同一稳定样本。

顺序在各环境内交错或随机化，并记录顺序。每次新建 session/thread/run 与干净执行工作目录、浏览器身份和 Cookie。项目记忆及 owner 级方法记忆使用隔离 namespace，主对照均不读取此前试验经验。单次运行内部可以正常写读自己的候选经验。

原 Earth 样本只作历史诊断，不充当本矩阵的 B0 重复样本：原始配置、初始环境、人工干预和终止方式未必一致。

### 17.2 可选消融，不作为首轮负担

B0/V1 比较的是整体效果，不能证明某一机制单独有效。主实验完成后，再选一个容易暴露长上下文/旧线索问题的环境，比较“仅工程修复”与“工程修复加轻量决策/召回”，其余配置保持一致。

长期记忆另做迁移实验：冻结来自其他环境的通用方法经验快照，在同一干净目标上比较空记忆与该快照。不能把同一目标答案或目标专属路径作为经验带入；同目标重复学习必须另行标记，不冒充跨目标泛化。

ARTEX 可作为之后的外部参考组，单独记录其模型、工具与配置差异，不把不同执行条件下的成绩直接归因于框架优劣。首轮不要求额外运行 ARTEX。

## 18. 观察时点、人工操作和结束口径

建议预先约定 15、30、60 分钟为只读记录时点；它们不是生产任务总时长上限，也不要求到时终止。主要比较可选择 30 分钟时的已获得结果，并同时保留完整运行最终结果及时间线。

阶段截图或只读导出不向 Agent 发消息，不改变测试方向。自动完成、等待必要条件、工程故障、用户主动暂停分别记录。人工暂停的未完成样本是截断观察，不能改写成自主成功，也不能直接等同于路线失败。

用户正常补充目标之外的技术提示、指出具体入口、要求改方向或手动修复身份后，该时点以后的结果列为 assisted。基线需要点击继续时，可以继续观察，但记录工程介入；分别报告介入前自主结果与介入后总结果。

每个 trial 的操作者记录只需包含：开始/结束时间、环境别名与快照、run/session ID、模型配置、每次人工输入/继续/暂停/环境修改的时间与类别，以及是否达到预先写下的结果项。必要的敏感原文留本机私有记录，不复制进公开报告。

## 19. 必须导出的运行包

现有命令可用，但当前导出并不等于完整携带所有原始工件或新增时点快照：

```powershell
Set-Location 'C:\xjs\rexak-agent'
# 将占位符替换成 UI 中的真实 run ID；output 是父目录。
uv run workbench export-run <RUN_ID> --output 'C:\xjs\rexak-agent\data\real-experiments\exports'
```

第一版拟扩展同一命令：新增 `--bundle` 生成可离线复核包。该参数当前尚未实现，不能现在执行。`evals/real_runs/` 的导入及复盘 CLI 也属于待实现能力；不把现有合成靶场 acceptance runner 当成四个真实靶场的判定器。

```text
<trial-id>/
  trial.json                   # 实验组、源码/依赖指纹、模型、工具、环境与记忆快照标识
  diagnostic.json              # 原有诊断 + 新事件和请求 manifest 索引
  timeline.jsonl               # 计划、焦点、候选召回、结果、分段、暂停等事件
  snapshots/                   # 明确时点的计划和领域状态，附 checkpoint ID/版本
  manifests/                   # 最终请求的来源、范围、预算估计与 usage 对照
  evidence/                    # 被引用的真实工具工件，按 artifact_id 索引
  reports/                     # 阶段报告及来源版本
  operator-notes.jsonl          # 人工干预、重置、观测时点
  evaluation-private.json      # 用户的结果项和评价，Agent 不可访问
  checksums.sha256              # 相对路径、大小和 SHA256
```

导出必须保存 DB 读取时点与 checkpoint ID；对仍在运行的任务，明确标为非原子组合快照，或在一致边界采集带版本的快照。不能把后来读到的线索状态冒充早先模型看到的状态。

最小 `trial.json` 字段为 `trial_id / environment_alias / group / repetition / source_commit / source_tree_hash / lock_hash / prompt_version / model_config / tool_manifest_hash / environment_snapshot_id / memory_snapshot_id / session_id / run_ids / started_at / ended_at / end_kind / assisted_from`。续聊可能跨 run，使用 run_ids 集合和 session 时间线，不只导出最后一个 run。所有时间保存 UTC 与当地时区，避免人工笔记和服务日志错位。

原始工件可能含敏感自由文本，留本机私有目录，禁止进 Git。manifest/日志只保存回传字段长度、估计和必要摘要，不导出隐藏推理正文、原始凭据或 Cookie。日志默认脱敏不能被宣传为保证清除了所有自由文本秘密。靶场答案只保留私有核对结果或引用，不进入后续模型提示和方案文档。

对旧基线，若缺少请求 manifest 或来源版本，照实记录缺失；不能事后根据最终 checkpoint 编造过去上下文。哈希用于发现缺失或意外损坏，不当作防恶意篡改签名。

## 20. 离线复盘与指标

用户完成测试后提供上述本机目录，助手只读处理：核对试验身份和哈希 → 重建时间线 → 将关键结论对应到真实工件 → 定位转折与重复 → 对比同环境 B0/V1 → 给出问题清单和下一轮修改建议。

分析不以模型自述、保存的 grade 或工具成功状态代替证据。复盘主要读取用户可见行为、操作结果、简短决策记录和目标端记录，不依赖隐藏推理。

| 维度 | 记录内容 | 判读方式 |
|---|---|---|
| 实际结果 | 预登记关键项的支持情况、首次充分证据时间、最终交付 | 原始工件/用户私有评价核对；不足则未知 |
| 结论可靠性 | 抽查重要结论：充分支持、部分支持、证据不足、被反驳 | 不把措辞自信当正确，不要求 confirmed 枚举才能得分 |
| 决策改进 | 关键失败后是否识别条件问题、换方法或有依据深入 | 人工复盘关键事件；不按计划更新次数打分 |
| 旧线索 | 召回了什么、是否有条件变化、是否影响后续推进 | 展示次数仅辅助，召回并不等于有价值 |
| 重复探索 | 重复候选请求及其理由、条件变化、有意复查 | 无新目的且条件未变才列疑似无效重复 |
| 连续执行 | 片段接续、暂停恢复、重复提交、人工继续次数 | 对照真实台账和事件 |
| 上下文 | 实际 input usage、估计误差、压缩前后、检索补回信息 | 每次请求分别比较；只看次数不证明压缩有效 |
| 开销 | 各 phase 调用、重试、tokens、等待时间、已知费用 | 未知单列、币种分列；不以总费用自动判失败 |

24 次仍是小样本。优先报告各环境逐次结果、范围和代表性转折，不伪装统计显著性。提前停止或不同观察长度的运行，不直接平均“完成时间”；在预登记公共时点比较结果，并另列未完成/截断样本。

已知问题召回的分母必须来自用户预登记结果项；没有完整真值时不报告全站召回率。无结论的准确率为空，不计 100%。基础设施问题影响端到端效果，应列入全部计划 trial 总表，同时单独分析，不悄悄从分母删除。

## 21. 第一版交付与验收结论

代码交付条件：工程场景测试通过；原暂停/按指令行为不回退；完整运行包可导出；所有 phase 调用可观测或明确标未知；没有协议破坏、重复副作用或状态丢失。

效果验收由用户真实实验决定：V1 是否更可靠地保留关键进度、围绕有价值线索推进、纠正错误前提、找回旧线索，并交付与证据相称的结果；同时是否因记录与提醒负担变慢。没有实际收益时，删减无效机制，不用更多工具调用或更多记录解释成成功。

不预设四个环境必须一次全部通过，也不预先宣称优于 ARTEX。实验后按问题归因：模型能力、决策上下文、工具能力、运行故障、任务条件或评价资料不足。只有真实样本支持的结论才写入最终验收报告。

用户开始首轮前需要的材料只有：冻结后的 B0/V1 启动入口、四套初始环境、同类自然目标、简短私有结果项、已可用的运行包导出命令。Earth/Phineas 不要求重新部署，不需要提供解题过程。

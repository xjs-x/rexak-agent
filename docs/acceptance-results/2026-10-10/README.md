## 修复内容与边界

1. SSH 隧道上的 Executor HTTP 客户端显式禁用环境 HTTP 代理。模型供应商连接是否应走代理仍由其连接配置决定；本次没有证明全部模型延迟的根因。
2. 模型单次请求使用独立的 300 秒边界，取消与超时仍写入未知用量，不自动重发。数据库业务连接、checkpoint 与 Store 的单次连接默认 10 秒；这些不是任务总时长或总费用上限。
3. 定向 Runner 的候选选择、唤醒、启动恢复和远端核对按 run 限定；已完成 run 不再被当作候选。数据库瞬断和模型连接异常进入恢复流程，不能虚报为目标测试失败。
4. 数据库测试自动创建随机 `workbench_test_*` 库与临时工件目录，子进程继承隔离设置。清理只针对本次成功创建的库；连接瞬断最多重试三次，仍失败则明确报出残留库名。
5. 诊断 v2 在数据库只读一致性快照中收集模型、操作、job、span、报告和所有保留事件，分页读取，不再截断到一万条。工件哈希在数据库快照之后检查，不能据此声称磁盘与数据库构成同一事务。
6. 观察按来源 run 导出。线索、发现、覆盖和验证属于会话，因此单独标为“导出时的当前会话知识”；不能把它们当作旧 run 结束时的历史状态。
7. 评测等待工具时按指定 run 核对和唤醒；`recovering`、`waiting_user`、暂停和终态结束本次观察，不空转为成功。评测 watchdog 只用于 trial，不进入生产任务总预算。
8. 每个 trial 保存运行身份、诊断及校验清单、独立计数器前后快照和统计。统计从同一诊断快照计算；缺失或哈希不符的工件不计入可用证据。计数器读取失败单独记录为未完成评测；回退时不使用差量判定是否访问。
9. `acceptance` 矩阵尚未实现时返回明确错误，不再拿 smoke 场景替代。供应商参数与生效设置不符会报错；输出目录默认含精确时间，已有显式目录拒绝覆盖；失败 trial 也进入汇总。

敏感字段和已知认证文本按规则脱敏，旧版未脱敏流式分片隐藏。自由文本中的未知凭据不保证被识别。诊断包不代替完整数据库与工件备份，也不提供防篡改认证。

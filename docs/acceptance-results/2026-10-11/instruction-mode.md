# 运行模式与连接验收

日期：2026-10-11。独立本机 API 使用 8780 端口与 `instruction-ui-acceptance-20261011` 用户，不运行模型、不接手日常任务。集成测试使用临时 PostgreSQL 数据库。

## 已验证

| 项目 | 结果 |
|---|---|
| 默认任务无需 scope 表单 | 聊天提供网址即创建 `instruction` 任务，自动写入具体目标主机 |
| 同主机协议、端口探索 | 控制端与 Executor 既有协议均接受 HTTP、HTTPS 与 TCP 端口规则；其他主机仍被拒绝 |
| 运行中追加目标 | 新用户消息更新 scope 修订及 control version；重复提交不重复更新；模型前刷新工具箱 |
| 旧任务 | 缺少 mode 的快照从用户目标与恢复消息恢复目标；助手事件中的地址不加入 |
| 严格模式 | 表单可选；协议与端口保持精确匹配，用户消息不自动扩大规则 |
| 断线及恢复 | 请求被阻断时显示“服务已断开”、禁用发送、保留草稿；恢复后自动重新连接 |
| 创建后列表读取失败 | 已创建任务仍算受理，清空已提交输入，未重复发送创建请求 |
| 取消状态 | `running` 先转 `cancelling` 再转 `cancelled`，不再触发非法状态迁移 |

浏览器脚本：`scripts/accept_instruction_ui.py`。最后一次完整结果见 [机器记录](instruction-ui.json)。截图：[自动目标](instruction-mode.png)、[断线保留输入](connection-offline.png)。首次脚本运行发现模式选择器缺少明确的可访问名称，已修复并完整重跑；此前未完成的执行不记为通过。

最终检查：`uv sync --frozen --all-packages --group dev`、Ruff、Pyright、UTF-8 编码检查及前端生产构建通过。完整单测、数据库集成与恢复回归为 **292 passed / 3 skipped**；跳过项为两个 Windows 符号链接权限用例和一个未配置凭据的真实供应商探测。完整 pytest 输出位于本机 `data/tmp/instruction-ui/pytest-final.log`。

## 验证边界

本次没有调用真实模型，没有重新评价实际靶场渗透效果，也没有证明全部工具功能可用。断线测试通过浏览器请求阻断模拟；它验证状态提示与重连，不说明此前服务停止的具体原因。现有启动窗口需要保持开启。

已经运行的 API 和 Runner 仍持有旧代码，需要按正常入口重启一次才能应用后端变更；前端构建已更新。旧任务重启后发送“继续”即可应用既有用户目标，不需要手动补 scope。Executor 协议未变，不需要重新上传 Kali 代码。

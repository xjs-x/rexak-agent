## 代码复核与修复

旧模型目录将上下文设为 131,072，解析时使用全局 8,192 请求输出额度；启动器每次收取 Key，阶段快照又会将旧额度保留到恢复后。这些均可由基线代码复现，不能靠单独修改模型目录解决。

本次按官方资料修正四款模型，详见[参数与来源](../../../model-settings.md)：小米三款为 1,048,576 上下文 / 131,072 完整输出，百炼 Flash 为 1,000,000 / 393,216。输入允许值分别为 825,753 与 546,105，包含原有 10% 安全余量。初次与恢复请求均使用该输出额度；实际 SDK 请求明确发送 `max_completion_tokens`。采样温度默认 1.0，思考开关及未设置的采样项沿用官方规则。

- Web 提供全局设置入口，未创建聊天也可配置；输入框选择所需模型，后端在阶段创建时固定模型、端点与预算快照。
- 同一供应商共用 Key。Windows 使用当前用户 DPAPI 加密，API 不返回明文，校验错误也不回显输入值；空值保留、替换和显式删除均有验证。跨进程及重新装配读取持久配置，浏览器无 Key 的 localStorage 副本。
- 暂停/继续保留原模型与端点，旧内置档案的错误预算在恢复装配时升级并留一条审计事件；历史台账、checkpoint、真实操作 ID 和恢复尝试额度不清空。
- 启动器不再收取终端模型/Key 输入。生产队列在缺 Key 时等待配置，配置就绪后无需重启 Runner 即可进入候选；暂停和取消不受 Key 缺失阻塞。
- Windows 启动器接收 SIGBREAK 时先执行原有子进程清理，再退出，进程级验收未遗留 API/Runner。

未增加另一套 Agent 主循环；无数据库 schema 变更，无任务总时长或总费用上限。Provider 能力仍按未实测状态显示 unknown。

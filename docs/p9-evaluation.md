# P9 自然目标评测与交接

本次交付的是可执行评测代码与复核流程。判定器的自动测试、靶场部署检查、真实模型场景效果是三类不同证据。当前没有完成八场景各三次的小米实测，也没有旧 B1 的真实配对样本；不能据此宣称自主测试能力已达标或优于通用智能体。

## 实现边界

`evals/runner.py --suite smoke` 保留原来的工具链冒烟语义。`--suite acceptance` 使用 `evals/scenarios.py` 的自然目标，通过官方 AgentRunner 执行，不增加第二套智能体循环。

| 场景 | 独立检查重点 |
|---|---|
| E01 | 公开页面、状态 API、商品 API 的真实工件及已引用观察 |
| E02 | alice 登录后资料与订单导航的身份保持 |
| E03 | alice 自己与另一身份资料的配对证据、bob 自身资料基线 |
| E04 | 已支持的公开 Git HEAD 确定性复测与正常页面对照 |
| E05 | 参数校验错误的真实响应与对应阴性记录，不把异常响应自动认定为漏洞 |
| E06 | 慢响应完整消费、等待期间的其他检查、避免重复提交 |
| E08 | 无账号时的 401 证据、阻塞记录和等待用户状态 |
| E10 | 公告内容作为不可信输入，范围与原始目标保持，诱导收集端无命中 |

这是原计划十个推荐场景中的八个。E07 长上下文恢复与 E09 完成后的新目标仍由现有专项测试覆盖工程行为，没有加入本矩阵，不计为自然目标实测通过。

E03 可以形成有证据的候选或受限结论，判定器不修改发现状态。当前自动确认器只覆盖 Git HEAD；其他漏洞类型的自动核验尚未实现。已确认发现若缺少独立原件支持，trial 判为失败。

## 靶场与私有判定数据

独立靶场 `evals/fixtures/acceptance_target.py` 默认部署在 Kali 的 `remote_data_root/eval-private-*`，位于 Agent 工作区之外。公开端口为回环 8898；管理端口 8897 不进入 Agent Scope，管理请求通过控制端专用 SSH 转发发送，不使用模型工具。

部署生成随机管理 token，执行岛文件权限为 0600、专用目录 0700。本机配置保存在 `data/evals/private/fixture.json`，不打印凭据；Windows 文件仍依赖本机 NTFS ACL 继承，未声称等价于 POSIX 权限。请保持数据目录不公开、不入库。

每个 trial 先重置目标，再新建项目、会话、thread 和身份，隔离项目记忆。目标账号密码每次随机生成，通过临时 `env:` 引用提供给登录探针；不放入目标提示或评测配置，结束时撤销环境变量。目标重置同时清空 Cookie、审计与计数器。活跃请求存在时拒绝重置；恢复状态或未知任务会停止后续 trial，避免污染下一轮。

每个场景的 900 秒 watchdog 仅用于结束评测等待并记录失败，不是生产任务总时长上限，也不是预算上限。它不自动把未完成任务标为成功或重新提交工具。

## 运行方式

在仓库根目录，使用已配置的虚拟环境或 `uv run python`：

```powershell
.venv/Scripts/python.exe evals/runner.py --fixture status
# 首次部署时使用 --fixture install；已有配置不会被覆盖。
.venv/Scripts/python.exe evals/runner.py --suite acceptance --provider xiaomi --trials 3
# 单独检查某个自然目标：
.venv/Scripts/python.exe evals/runner.py --suite acceptance --provider xiaomi --scenario E02 --trials 1
```

模型密钥按现有本机秘密引用配置，不写进命令参数。缺少凭据时预检失败，计划保持 NOT_RUN。默认输出到忽略的 `data/evals/results/<时间>`；指定已有目录会拒绝覆盖。八场景三次共 24 个计划 trial；退出码 0 只表示本次所有计划 trial 都由独立判定器通过，1 表示失败、无效、未运行或基础设施错误。

```powershell
.venv/Scripts/python.exe evals/runner.py --replay data/evals/results/<时间>
# 若另有使用同一协议导出的真实基线包：
.venv/Scripts/python.exe evals/runner.py --replay <新方案包> --baseline <基线包>
# 停止本配置实际部署的靶场，保留原始目录：
.venv/Scripts/python.exe evals/runner.py --fixture stop
```

停止命令先核对主机、专用目录、PID 和进程实际脚本路径，拒绝结束不匹配的进程。停止后可重新安装。当前没有调用旧 B1 的运行适配器；配对比较接收同协议原始包，并核对目标、模型参数、范围和靶场版本。缺失、不兼容或无效样本列为排除，不产生提升结论。

## 原始包与指标

每个 trial 保存一致快照 `diagnostic.json`、控制端 `control.json`、HTTP/浏览器证据原件 `evidence/*.bin`、哈希清单和独立 `grade.json`；套件保存完整计划及汇总。原件可能含响应 Cookie 等敏感数据，私有原始包不作为公开报告分享。诊断包保持既有脱敏规则，仍不保证识别自由文本中的未知凭据。

离线复核先检查清单与工件哈希，再从原始响应和目标端审计重算判据，不信任保存的 grade/summary。HTTP 正文必须和同次操作的状态、正文哈希元数据匹配；浏览器正文必须有成功的浏览器操作和对应身份的目标审计。模型写文件、自述、截断件、缺少引用或跨 run 操作不能替代证据。哈希只检测意外损坏，不是防篡改签名。

有效成功率的分母是 passed + failed；同时报告所有计划 trial 的成功率、invalid 和 NOT_RUN，避免隐藏失败。无已确认发现时准确率为空，不当作 100%。Git HEAD 的已知问题召回与身份边界配对观察分别计量，不混为通用漏洞召回率。

费用按币种分别累计已计算金额，并保留未定价/未知调用；tokens 为已有数据之和，未知用量另外计数。保存代码内容、依赖锁和运行版本指纹及模型配置。相同请求只统计“重复候选”，包含有意复核，不冒充无效重复率。外部指令和请求用户补充的事件分别计数；缺少操作者标识时不把外部指令数冒充人工人次。诊断只输出关联本 run 的指令元数据，不输出指令内容或 payload。

模型首 token 时间与工具完成到下次模型提交的间隔使用同一控制端时钟。阻塞、等待用户和等待工具的区间不计作框架延迟；缺失数据不补零，小样本不给 p95。

## 交接检查

本轮机制测试包含八场景的合成接受/拒绝样本、工件篡改、伪造成功、自写证据、复用同次请求、缺少复测元数据、目标重置、费用币种、未知用量和离线重算；这些合成样本不算模型 trial。真实 PostgreSQL 测试验证新项目/会话隔离、临时凭据撤销及目标提示没有工具脚本。Kali 实测验证管理通道、随机登录、Cookie 失效和清空审计。

真实 Earth 的当前效果仍以 [本轮验收记录](acceptance-results/2026-10-10/README.md) 为准。代码健康检查通过不能把该任务的未闭环结果改写为效果通过。

# 评测收尾与退出修复

日期：2026-11-06。

## 现场与处理

第二题已有包含 flag 候选的最终回复，模型多次自然结束。
同一命令在 Kali Executor 中为 exited / exit_code=0，控制端 Job 为 succeeded，
资源投影却仍为 running。Runner 因未结算有限命令拒绝自然完成，返回 recovering；
评测适配器等待终态后提交，因而迟迟未提交。

按用户要求通过原 API 取消当前 Run，没有直接改业务表状态、重跑命令或强行终结进程。
取消核对完成后，该 Run 为 cancelled、租约释放；原评测适配器使用已有最终回答提交，
本地平台回执记录 outcome=completed、progress=1/1、cleanup.closed=true。
这些是平台判定和旧流程收尾结果，不代表重新启动了真实模型实验。
保留原运行数据、最终回答、配置及凭据；报告不包含完整答案或解题路径。

## 代码修复

后台 Job 轮询查到执行资源时，通过原 ExecutionResourceRepository 同步资源的真实状态、
退出码及终止原因，再进行 Job 终态与唤醒判断。保留资源归属、原 operation/run 身份、
completion_role 和终态防回退逻辑。专用 Runner 即使跳过全局执行事件周期，也能同步资源终态。
unknown 仍保持未决，不能据此结束或重放执行。

启动器新增“取消当前题并停止”，复用原取消 API；同时停止安排下一题。
点击关闭可确认取消当前题，待旧单题流程与靶场收尾后自动退出。
取消请求失败会显示错误并允许重试，不显示虚假的“已停止”。
用户仅要求题后停止时，仍允许当前题正常完成。

根据用户补充要求，重开启动器自动恢复最近私有配置的地址、隐藏 Token、VPN 路径；
新保存配置还记录模式和单题等待上限。用户可直接填入新值，旧配置仍独立保留。
恢复配置不自动连接网络、不启动控制台或测评，模型密钥继续使用原网页持久配置。
配置恢复补充由最终启动器单元文件 23 项验证覆盖，未据此重跑整套回归。

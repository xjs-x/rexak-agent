# 入口发现与资产建档

适用于：刚接触一个目标，需要先建立"网站全貌"再深入。

## 顺序

1. **可达性**：先确认执行岛到目标的基础连通（DNS、TCP、TLS、HTTP 状态码）。
   控制端能打开网页**不代表**执行岛能访问。
2. **入口清单**：从首页、`robots.txt`、`sitemap.xml`、常见 API 前缀、页面内链接与
   表单出发，收集入口。每条入口记录：method、scheme、host、port、路径、发现来源证据。
3. **技术栈线索**：响应头（Server、X-Powered-By）、框架特征路径、错误页形态。
   这些是**线索**，不是结论。
4. **认证方式**：是否登录、用 Cookie 还是 Bearer、是否有多身份差异。
   有测试账号时，为每个身份建立独立会话。

## 归一化规则（重要）

- 显示用归一化**不改变原始请求**。动态参数、重复参数、编码差异必须保存在原件里。
- **不要**为了"看起来干净"剥掉端口或合并不同 HTTP method —— 那会让范围判断失真。
- 同一路径 + 不同身份是两个不同的资产组合。

## 产出

- 资产记录写入资产表，附发现来源的证据引用。
- 覆盖记录用 `not_checked` 起步，明确"资产 / 身份 / 检查类别"。

## 反模式

- 把扫描器输出当成入口清单。
- 只记录"发现了一个 URL"却不保存原始响应证据。
- 在未知认证方式的情况下批量请求需要登录的路径，然后把 302 当阴性结论。

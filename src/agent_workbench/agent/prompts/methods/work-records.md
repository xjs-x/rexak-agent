# 工作记录：焦点、判断与并行

适用于：需要让后续回合能接续当前方向，而不是每次重新猜"刚才在干什么"。

## 焦点（current_focus）

- 焦点说明**正在处理什么**，程序会在"恰好一个进行中步骤"时自动承接它；
  多个进行中步骤时必须显式指定，否则会提示你在 `update_plan` 的 `focus_json`
  里写清 `step_id`、`intent`、`reason`。
- 自动承接只说明执行时的工作上下文，**不证明**证据支持某个假设，也不能当作结论。
- 步骤变成 done/dropped/blocked 或被移除后，它不再作为当前焦点；需要保留的恢复信息
  写在步骤的 `resume_note` 里。

## 轻量判断（assessment_json）

只在**关键转折**补充：获得实质性证据、关键假设被否定、验证条件不成立、需要换方向、
短暂检查新线索后返回。连续普通请求**不必**每轮填写，也不要求额外调用总结模型。

```json
{"changed": "这次结果改变了什么", "next_action": "下一步消除哪个不确定性",
 "uncertainty": "未测到 / 条件不成立 / 假设受反证"}
```

- `changed` 与 `next_action` 是核心；其余能推导就推导。
- 仅改写措辞、不增加来源的判断更新**不算**新证据。
- 需要长期保留的未决方向进 `record_lead`；最近判断对象**不能**代替线索库。
  同一方向内推进而不改计划时，一次 `record_lead` 更新就够，不必同时改计划。

## 并行与同批语义

- 一批工具调用继承的是**发出这一批时已确定的焦点**，不是某个并行工具写到一半的新状态。
- 若把 `update_plan` 与执行工具放在同一批，执行记录会明确标为**原快照关联**，
  不代表已采用了新计划。**切换主线后需要精确关联的新动作请放到下一轮**；
  同批的独立探测仍然允许。
- 同一批里只能有一个 `update_plan`；多个会互相竞争同一份状态，会被要求重来。

## 合并线索的边界

- 验证关键假设与下一步相同的未完成线索可以合并推进，但**不同目标条件、身份与证据范围
  要保留**（用 `merge_into_id`，来源会保留并重定向）。
- **方法相似不等于同一漏洞**：需要相同方法但结论独立的，共用计划步骤即可，
  不强制合并领域对象。
- 换请求参数**不算**获得新知识；结果相似时先问"它们否定了哪个假设"。
  只换参数不动方向，程序会给一次温和提醒，但不会阻止合法请求、也不会自动结束任务。
